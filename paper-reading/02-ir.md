## §4 开头两段与 Listing 5（PDF 第 4 页）

第一段把 IR 放在源代码与设备代码之间。IR 是给编译器读写的程序表示，保留了元素类型、块形状和操作之间的依赖。论文把生成过程概括在解析阶段；v0.1 的[运行时](../../triton-legacy/lib/runtime/function.cc#L191)有可单独跟踪的两步，`Parser::Parse` 生成 AST（语法树），`Generator::Gen` 读取它并创建 IR。第二段解释保留 LLVM 风格的函数结构，再给整块数据与整块条件增加表示。下面先用一条 masked load 读旧指令怎样保存输入和类型，再回到论文的 ReLU 清单比较。

按 Listing 5 从上往下读。该函数表达 ReLU，也就是把小于 0 的输入变成 0，其他输入保持原值。百分号开头的名字指向 IR 值。比如 `%rm_bc` 表示一次广播操作的结果，可以再作为下一条操作的输入。

<a id="mask-to-builder"></a>
### 亲手从一行 masked load 追到 builder

从[旧 dot kernel](../../triton-legacy/tests/common/src/dot.h)的循环找 `a = *?(checka)pa;`。先把它读成「对每一项，如果 checka 对应项为真，则从 pa 对应的地址读」。这里 `*?` 是旧 Triton-C 给解引用加条件的写法。往上一层读编译器时，手里的 `checka` 和 `pa` 是程序节点所指的 IR 值。编译器此刻还不知道运行时每项的真假和地址。

1. **认语法。** 在 [Parser::ParseUnaryOp](../../triton-legacy/lib/lang/parser.cc#L644) 内读 `BinaryOp::New(tok, Token::MASKED_DEREF, pred, addr)`。`::` 表示到某个作用域里找名字，这里调用 `BinaryOp` 内的 `New`。以 `*?(checka)pa` 为例，`pred` 代表括号里的 `checka`，`addr` 代表后面的 `pa`。它建立一棵小树，根记录操作类型是 `MASKED_DEREF`，左子节点是 `checka`，右子节点是 `pa`。所以第 2 步的 `rhs` 会变成地址块。
2. **把语法读成 IR 输入。** 打开 [Generator::VisitBinaryOp](../../triton-legacy/lib/lang/code_gen.cc#L20)。`Visit(binary->rhs_)` 处理右子节点，随后的 `rhs = ret_` 保存它生成的 IR 值；类似地再得到 `lhs`。`->` 表示通过指针访问对象的字段或方法。这里的两个结果分别表示地址和真假块。
3. **决定该造哪条 IR。** `switch(binary->op_)` 按操作类型分支。找到 `case Token::MASKED_DEREF`，最后的 `bld_->create_masked_load(rhs, lhs, false_value)` 依次传入指针、mask 和被屏蔽位置的替代值。`bld_` 是 builder 对象的指针，builder 负责构造并登记 IR 操作。
4. **看清无效位置交什么值。** 这条分支先造 `undef_value`；如果是 tile，就用 `create_splat` 把它变成每个位置都有同一未定义标记的一块。旧 dot 循环前另有 `checka ? *pa : 0`。搜同文件的 `VisitConditionalOp` 或 `create_masked_load` 的另一处，可查到后一种写法怎样提供零作为备选。读其他 kernel 时，要看 mask 为假时需要填零、填别的值，还是这一项永远不会消费。

现在把 builder 后面的一小步走完。打开 [builder.cc 的 create_masked_load](../../triton-legacy/lib/ir/builder.cc#L262)。这一行把三个值交给 `masked_load_inst::create`，再用 `insert` 把新节点放进当前 IR。为了回答「load 的输入最后挂到哪」，只跳到 [instructions.cc 的 masked_load_inst 构造函数](../../triton-legacy/lib/ir/instructions.cc#L453)，读三句 `set_operand`，分别对应地址、mask、替代值。`load_inst(ptr, ...)` 是结果类型的来源，它会沿地址的类型推导读出来的值是什么。[下面的 type.h 走读](#read-tile-type)正好解释这个交接。

如果想确认「输入和使用者怎么联系起来」，再跟一层到 [value.cc 的 set_operand](../../triton-legacy/lib/ir/value.cc#L43)：`ops_[i] = x` 记下第 i 个操作数是谁，`x->add_use(this)` 从 x 反向记下当前操作使用了它。`this` 是正在执行这个成员函数的对象，其值在这里指向新建的 load。例如 `set_operand(1, mask)` 之后，load 的输入 1 指向 mask，mask 的使用者集合里也多了这条 load。马上回到 load 处，把这行记成「load 记下三个输入，输入也记得这个 load」。后面 pass 才能沿这些关系找出谁要换输入。其他构造类可以等遇到再读。

例如首轮的 `checka ? *pa : 0`：设两个地址是 `[100,104]`，`checka=[true,false]`，地址 100 里的值是 7。结果是 `[7,0]`，地址 104 无须被读取。对照同一文件的 `a = *?(checka)pa`，这条语法构造的假项替代值是 undef，不能按 0 推导后续算术。回到论文 Listing 5，问「哪条访存指令实际拿到了比较产生的 mask」：印刷清单虽然先定义了 `%msk`，所列的 load 和 store 都没有这个操作数。

### 读懂三层循环在遍历谁

[peephole::run](../../triton-legacy/lib/codegen/transform/peephole.cc#L192) 连写三个 `for`：`for(ir::function *fn: mod.get_function_list())` 逐个取模块里的函数，`for(ir::basic_block *block: fn->blocks())` 逐个取当前函数的基本块，`for(ir::instruction* i: block->get_inst_list())` 逐个取当前块的指令。冒号右边是可遍历的一组对象，左边声明这次取出来的单个对象。前两个 `for` 后面没有花括号，各自只把下一条 `for` 当循环体，所以最里面的代码才会对每条指令执行。

举例，一个 module 里有 `relu`，它的 `prologue` 块里有 `load`、`max`、`store` 三条指令。此时 `fn` 固定指向 relu，`block` 固定指向 prologue，只有 `i` 在三条指令间依次变化。上一节的 `value` 与 `user` 关系是另一条线：当 `i` 指向 max 时，它可以从操作数找到前面的 load。前一条线说明指令摆在哪个块，后一条线说明它和哪个值存在依赖。

## §4.2 Data-Flow（PDF 第 5 页）

<a id="read-tile-type"></a>
### 跟读 type.h：一块 tile 的形状怎样传给下一条操作

对应摘要里「编译时已知形状」和 §4.2.1 的 `i32<8,8>`。这次只跟一个问题：**一块有 2 行、3 列的 float，在编译器内靠什么让后面的操作知道它有 6 项？** 例子里的形状用于读类型代码。运行时的数组元素此刻还没有读进来。

#### 第一步：在声明里找存放位置

打开 [type.h 的 tile_type](../../triton-legacy/include/triton/ir/type.h#L183)，先只读 `class tile_type` 到它的右花括号。把这几行连起来：

```cpp
class tile_type: public composite_type {
    // 省略其他声明
    const tile_shapes_t& get_shapes() const { return shapes_; }
    // 省略其他声明
    tile_shapes_t shapes_;
};
```

这是帮助定位的节选。最后的 `shapes_` 是保存在每个 tile 类型对象里的字段。`get_shapes()` 交回这个字段供别人查看。`&` 表示引用已有对象，返回值前的 `const` 表示调用者不能通过这个引用改字段。回到 [同文件开头的 tile_shapes_t](../../triton-legacy/include/triton/ir/type.h#L21)，看到 `typedef std::vector<unsigned> tile_shapes_t` 就知道它是「一串有顺序的非负整数」的别名，例子的内容是 `[2,3]`。这里可以回到 `tile_type`，无需进 `<vector>`。

接着问一个字段里没有回答的问题：**float 放在哪里？** 头文件只给了 `tile_type(type *ty, const tile_shapes_t &shapes);` 的声明，分号前告诉你需要元素类型和形状。此时跟到实现有意义，因为要找 `ty` 保存到哪里。

#### 第二步：在实现里找元素类型

打开 [type.cc 的构造函数](../../triton-legacy/lib/ir/type.cc#L176)，读冒号起始的初始化和函数体：

```cpp
tile_type::tile_type(type *ty, const tile_shapes_t &shapes)
    : composite_type(ty->get_context(), TileTyID), shapes_(shapes) {
  contained_tys_.push_back(ty);
}
```

冒号后两项发生在进入花括号前。第一项让父类链记录所属编译上下文和 `TileTyID` 标签，第二项用传入的 `[2,3]` 初始化 `shapes_`。函数体把指向 float 类型的指针加入 `contained_tys_`。这个字段在祖先类 `type` 里；在 [get_tile_element_ty](../../triton-legacy/lib/ir/type.cc#L51) 只要确认它从位置 0 把这个类型拿回来即可。

调用者用的是 [tile_type::get](../../triton-legacy/lib/ir/type.cc#L196)。前面几行检查元素类型与形状列表，后面用「元素类型指针、形状」这对值查编译上下文中的表。同一个上下文里再次请求相同组合，会拿到已有类型对象；没找到才调用刚才看的构造函数。读到 `return entry` 就可以返回。已经知道类型对象从哪来，此时没必要从 `p_impl` 继续递归读整个 context。

#### 第三步：往上找谁把 float 和 [2,3] 交给它

打开 [code_gen.cc 的 GenIRTileType](../../triton-legacy/lib/lang/code_gen.cc#L684)，只读这个函数。参数 `TileType* type` 属于源语言的类型对象，返回的 `ir::type*` 属于 IR。两者之间是这样的交接：

1. `GenIRType(type->Derived().GetPtr(), ctx)` 取源语言元素类型再转成 IR 元素类型。本例只需回看[同文件的 T_FLOAT 分支](../../triton-legacy/lib/lang/code_gen.cc#L669)，核对它得到 IR 的 float。
2. `type->Shape()` 得到源类型里的 `[2,3]`。`for(int s: _shape)` 的意思是按顺序把每个尺寸交给 `s`。循环把尺寸转成 `unsigned`，放进刚才见过的形状容器。
3. `return ir::tile_type::get(ele_ty, shape)` 把 float 和这串数字交给第二步的入口。想确认这个函数在什么时刻被用，回到 [VisitDeclaration](../../triton-legacy/lib/lang/code_gen.cc#L334) 的 `GenIRType(obj->Type(), *ctx_)`，再查看 [GenIRType](../../triton-legacy/lib/lang/code_gen.cc#L638) 分派给 `GenIRTileType` 的那一支。读到这里，声明到 IR 类型的链就闭合了。想进一步追左方括号由谁识别时，再补读 [ParseArrayFuncDeclarator](../../triton-legacy/lib/lang/parser.cc#L1777) 中创建 `TileType` 的分支。

#### 第四步：沿消费者看到形状怎样继续流动

想象刚才读过的 `pa` 有 2×3 个地址，每个地址都指向 float。先到 [value.h](../../triton-legacy/include/triton/ir/value.h#L22) 看 `get_type() { return ty_; }`。IR 值持有类型指针，地址块这个值就能说出自己的元素类型是「指向 float 的指针」、形状是 `[2,3]`。随后直接跳到 [load_inst::get_pointee_type](../../triton-legacy/lib/ir/instructions.cc#L429)，按三行读：

1. `get_scalar_ty()` 从地址块类型取出单项类型，即指向 float 的指针。
2. `get_pointer_element_ty()` 再取该指针指向的类型，得到 float。
3. 地址值的类型是 tile，于是 `tile_type::get_same_shapes(pointee_ty, ty)` 继续沿用 `[2,3]`，元素类型换成 float。回到 [get_same_shapes](../../triton-legacy/lib/ir/type.cc#L208)，核对它确实把旧 shape 传给 `get`，然后返回 load 的调用处。

写下 `2×3 个指针 → load → 2×3 个 float`。现在可以回到论文 Listing 5 或继续读本节后面的广播：类型说明一块值长什么样，`value` 把它挂到实际的 IR 节点上，具体操作选择怎样用它。这里已经有一个创建者和一个消费者，可以先收起 `type.h`。

- **§4.2.1 类型段。** `i32<8,8>` 表示元素为 32 位整数、形状为 8×8 的一块值。沿[上面的类型走读](#read-tile-type)确认元素类型和 shape 的来源，再到[function::make](../../triton-legacy/lib/runtime/function.cc#L253)看配置如何在生成 IR 前被代入。
- **§4.2.2 开头、两个指令条目与 Figure 4。** reshape 可以把三个元素排成一行或一列，元素数保持为 3。broadcast 把大小为 1 的轴扩展到目标大小。图 (a) 是列 `[a,b,c]` 的每一行重复自己的值，图 (b) 是行 `[a,b,c]` 整行重复。去[GenBroadcastOp](../../triton-legacy/lib/lang/code_gen.cc#L518)找两次 builder 调用，画出中间和最终 shape。这里的重复是逻辑语义，后端可以由索引或布局实现。
- **§4.2.2 末段。** 普通比较、加法、指针偏移可以逐位置做，转置改变坐标排列，dot 要跨一个轴累加。看[VisitBinaryOp](../../triton-legacy/lib/lang/code_gen.cc#L20)的操作分派，沿其 builder 方法回到[指令定义](../../triton-legacy/include/triton/ir/instructions.h)。挑出 add 与 dot 比较输出 shape。

### 手算一遍 GenBroadcastOp 的三个中间对象

在 [GenBroadcastOp](../../triton-legacy/lib/lang/code_gen.cc#L518) 中，`src` 指已有的 IR 值，`dst_ty` 表示希望符合的目标类型。拿 `src=[7,9]`、目标 shape 为 `[3,2]` 来读从 `if(src_shapes.size() != dst_shapes.size())` 开始的分支。代码里 `.size()` 询问这个形状数组里有几个数字，也就是有几根轴。

1. 源形状有一根轴，目标有两根。两个元素数分别是 `2` 与 `3*2=6`，因此进入 `else`。
2. `padded_shapes.insert(padded_shapes.begin(), 1)` 在形状数组起点插入 1，得到 `[1,2]`。检查每一轴，新形状的 1 可以扩为 3，末轴的 2 已经相同。
3. `create_reshape(src, padded_shapes)` 把一维的两个值解释成一行两列。最后 `create_broadcast(padded, dst_shapes)` 表达后续三行都能用 `[7,9]`。这里创建了两个 IR 操作，编译器后面再决定如何实现这些读取关系。

此时如果右边还要加一个 `[3,2]` 的值，两个操作数的坐标现在对得上了。若发给此分支的源形状为 `[4]`、目标为 `[3,2]`，补成 `[1,4]` 后第二轴的 4 和 2 都不能扩成对方，能在检查中看见原因。

## §4.3 Control-Flow 与 Listing 6（PDF 第 5 页）

首段的问题可以用一个尾块理解：四个地址只有前两个有效，直接对整个块做一次普通 if，不能表达两个地址要访问、另两个要跳过。可以给四项各传一个真假值供访存操作使用。v0.1 的[三元表达式生成与 masked load](../../triton-legacy/lib/lang/code_gen.cc#L225)展示了这个具体路径。

第二段及两个指令条目提出 PSSA（Predicated SSA，把操作与条件一起记录）。Listing 6 可按以下顺序读：

1. 对 x 的每个位置比较是否小于 5。若 x 的两项是 2 和 8，则 `pt=[true,false]`、`pf=[false,true]`。两个条件互补。
2. `pt` 选择做加一的位置，`pf` 选择做减一的位置。假设 y 两项都是 10，左路提供第一项 11，右路提供第二项 9。
3. `psi` 按条件逐项合并得到 `[11,9]`，后续乘二得到 `[22,18]`。旧 `phi_node` 是按进入当前块的前驱选择值，粒度是控制流路径。

在固定 v0.1 的 IR 指令定义、生成器和编译序列中，尚未核实独立的 `cmpp`、`psi` 指令。比较现存实现时，可以读旧[masked store 构造](../../triton-legacy/lib/lang/code_gen.cc#L728)、现代 [`tl.load`/`tl.store`](../../triton/python/triton/language/core.py)里每个位置的 mask 合同，并记下各路径如何处理无效地址。论文模型与快照差异也见[第 2 章](../chapters/02-legacy-ir-passes.md#sec-2-2)。
